双手拿着 UMI 完成一段操作，多路相机从不同方向看见它，双 FR3 再照着轨迹运动。画面可以很像，曲线也可以很顺，但这还不能回答最关键的问题：**人手当时的 TCP 到底在哪里，机器人后来又是否真的经过了同一条物理轨迹？**

这个项目研究的不是如何得到一串更平滑的位姿，而是如何把一段双手演示变成可核验的度量事实，再把这份事实迁移到另一种机器人 embodiment 上。前半程需要证明 UMI 轨迹测得准，后半程需要证明双 FR3 复现得准；两次验收缺一不可。

目标是 TCP 平移误差 p95 ≤ 3 mm、旋转误差 ≤ 0.5°，静止 jitter 控制在 0.5–1 mm，tracking coverage > 99%，同时让双手相对位姿误差不超过 3 mm。**现在还没有达到这个结论。** 纯相机、rig 口径下的平移 p95 约为 5.5–7.4 mm，p50 约为 2.5–3.8 mm；真正进入训练集的 TCP 口径仍缺实物 Marker→TCP 标定，用于这组测量的 cube 的晃动也破坏了刚体假设。当前成果是把误差来源和认证路径钉住，而不是提前宣布“毫米级已完成”。

## 一条轨迹，需要两次独立证明

录制端和复现端有各自的内部坐标系，也都有看起来很漂亮的内部指标。多相机可以报告重投影残差，FR3 可以报告指令位姿与正运动学位姿之差，但这两类数字都只能证明系统内部是否自洽。

相机网络不能给自己的绝对精度发证书，FR3 的编码器和运动学模型也不能证明真实 TCP 已经到位。最终判断必须来自一套没有参与估计的动态 6DoF 测量设备。

| 环节 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 多相机角点与重投影残差 | 观测和模型是否互相解释 | 世界尺度、外参和 TCP 是否绝对准确 |
| FR3 编码器与 FK | 控制器和名义运动学是否一致 | 真实末端是否抵达命令位置 |
| 独立 6DoF tracker | 物理 TCP 的绝对与相对误差 | 训练数据语义是否正确 |

## 最容易误读的数字，是 0.2 mm

这套系统里同时出现过 0.2 mm 和 2 mm 量级的结果。它们并不冲突，只是回答了不同问题。

在同一次标定内部，外参参与拟合，也参与后续检查。外参若带有共同偏差，这个偏差会在两边一起出现并相互抵消。因此，held-out 3D 一致性 p95 0.244 mm、理论不确定度 p95 约 0.26 mm，只能说明当前相机布局在几何上具备亚毫米分辨能力，不能证明真实 TCP 已经达到亚毫米精度。

随着数据逐步独立，隐藏的系统误差才会暴露出来：

| 验证方式 | 观测到的差异 | 正确解读 |
| --- | ---: | --- |
| 同一套外参内的样本拆分 | 约 0.05 mm | 内部自洽性 |
| 同一轮采集重采样并重拟内参 | 约 0.61 mm | 求解与采样稳定性 |
| 换一整轮挥板采集再重解 | 约 2.54 mm | 暴露采集覆盖差异，尚不能当作合格的跨轮复现性 |

最后一项之所以仍不能叫“复现性”，是因为两轮采集并非各自完整覆盖全画幅：一轮缺外圈，另一轮中心欠约束。它证明的恰恰是**多采几帧不能替代多采有效姿态**。每一轮 episode 都必须独立满足画幅网格、径向分箱和外环角点覆盖，且门槛要检查求解器实际选中的帧，而不是只检查原始检出数量。

在取得真正独立的跨轮数据和外部 tracker 结果之前，生产预算中的相机项按 2 mm 量级管理。亚毫米内部结果仍然有用，但用途只有一个：判断相机布局是否值得继续改。

## 3 mm 不是单项指标，而是一张误差账

TCP 平移误差由多项误差共同构成。近似独立时，可以用下面的 RMS 预算理解：

```text
e_total ≈ sqrt(e_camera² + e_marker_geometry² + e_marker_tcp²
             + (L·θ)² + e_solver² + e_timing² + e_smoothing²)
```

这里最重要的不是公式形式，而是每一项都必须有自己的测量方法。任何一项都不能单独花满 3 mm，更不能把系统偏差指望成多相机平均后自动消失。

### 相机数量已经不是主要杠杆

系统物理上安装了 8 路固定 RGB global-shutter 相机，但 `cam_00` 视野被遮挡、检出为 0，因此所有标定和跟踪结论都按 7 台计算。工作区最弱方向的理论 p95 约 0.73 mm，held-out 3D 一致性 p95 为 0.244 mm。两条内部证据都指向同一个判断：几何条件足以进入亚毫米量级，继续加相机不会解决眼下的问题。

真正超预算的是外参，尤其是旋转外参。

`cam_09` 是最典型的例子。它看起来像有一段近似固定的平移偏置，实际根因却是 1.988° 的旋转误差。旋转误差在有限工作区内很容易伪装成常量平移；若直接减掉一个平移向量，只会在当前区域把错误藏起来。重新求解旋转和平移后，整机端到端复核的 p50 从 3.66 mm 降到 3.42 mm。

这项修正相对于留一验证散布的信噪比达到 42:1，而其他相机只有 2–3.4:1 或落在自身噪声内。因此只修 `cam_09`，不把每台相机都“顺手微调”。全相机 corner BA 的外点门在没有该先验的情况下，又把 98% 的剔除判给了 `cam_09`，形成了第二条独立证据。

### Marker Rig 本身也是尺子

相机看到的是 Marker，任务关心的是 TCP。二者之间隔着实物 rig 的尺寸、刚度、装配重复性和一段六自由度变换。这里任何一个“照 CAD 应该没问题”，最后都会直接写进标签。

旧高位 cube 到 TCP 的杠杆臂约 241 mm。换成低矮的分布式 rig 后，这一距离缩短到 102.3 mm。同样是 0.5° 的姿态误差，传到 TCP 的位置误差由约 2.1 mm 降到 0.89 mm。结构设计在这里不是包装，而是在直接购买误差预算。

分布式 rig 也不能再由“6 个同尺寸、共面、居中 Marker”的硬编码描述。现在的 layout 明确记录每个 Marker 的字典、ID 和四个三维角点，允许不同尺寸和非共面布置；角点几何必须由多相机测量得到，CAD 只提供先验。Marker→TCP 另存为独立标定，因为“rig 长什么样”和“任务点在哪里”是两件不同的事。

现役 rig 还没有完成这两份实测标定，这正是当前不能报告生产 TCP 精度的原因。

### 时间偏差会在运动中变成空间偏差

静态检查容易掩盖时间问题。已观测到的一侧设备时间偏移约为 4.4 ms；当 TCP 以 450 mm/s 运动时，它等价于接近 2 mm 的空间错位。真实操作中 rig 速度 p95 可达 680 mm/s，同一份毫秒级误差会更加昂贵。

因此多路相机共享硬件触发，设备时钟映射到同一时间轴，sidecar 直接读取 parquet 中的真实 timestamp；缺失时间列时任务失败，不允许用 `frame_index / fps` 猜时间。连续传感量按时间插值，接触和饱和事件保留原始高频语义，避免在对齐到视频帧率时把短促力峰平均掉。

速度还揭示了一个监控盲区：随着运动加快，逐相机弥散 p95 曾从 10.6 mm 升到 18.9 mm，融合重投影残差却只从 3.68 px 变为 3.81 px。逐相机弥散只是诊断上界，不是标签误差；但它足以说明，动态退化未必会在常用残差中报警，质检必须按速度分层。

## 生产管线只接受可追溯的轨迹

单帧 corner BA 把所有相机看到的原始角点放在一起，只求同一个刚体位姿。它比“每台相机先估 pose、最后再平均”保留了更多观测信息，也能为每一帧给出协方差、可见相机数、残差和失败原因。

在此基础上，生产管线遵守四个契约：

1. 解不出的帧保持 `unsolved` 且 `σ=inf`，不回退到一个看似完整的 pose 平均结果。
2. 离线 SE(3) batch smoother 根据信息量调整整段轨迹，gap 处切段，原始轨迹永久保留；因果 EMA 只用于分析。
3. 每条 episode 和每次标定都携带 `world_frame_id`。相机整体移动会产生 continuity break，但不会改写历史数据的坐标系出处。
4. sidecar v2 的质量字段必填，并与 v1 在训练集汇聚层显式隔离。v1 的 pose 平均加 EMA 与 v2 的 corner BA 加 batch smoother 不是同一种标签，不能静默拼接。

这不是单纯的 schema 洁癖。新估计器曾让左右手标签相对旧管线分别移动约 10.3 mm 和 7.7 mm。只要测量链的含义发生变化，数据版本就必须把差异暴露出来，而不是用兼容代码把它抹平。

## 双 FR3 复现，难点不是把轨迹发出去

UMI 和 FR3 的机构、工作空间与冗余自由度不同。把 TCP 位姿逐帧交给 IK，最多能得到一段“每帧都有解”的关节序列，不能保证双手关系、肘部连续性、碰撞裕量和真实物理轨迹仍然成立。

要让复现仍然忠于原演示，必须守住四个不变量。

### 1. 世界尺度不能在部署时重新解释

两台 FR3 的运动学只定义在各自 base frame 中，必须先注册到同一个 canonical metric world。当前写成 `T_WB = T_WP · T_PB`：多相机测量平台上的刚性 ArUco rig 得到 `T_WP`，平台到机械臂基座的外参 `T_PB` 预先标定。

平台一旦移动，旧的 `T_WB`、双臂碰撞场景和 absolute replay transform 同时失效。Marker 也必须固定在与 base 共刚体的承力结构上；贴在薄钣金或塑料罩上，测到的只是 panel motion。

### 2. 双手关系不能被两次对齐拆散

左右手若分别做 first-frame alignment，会各自产生一个 `A_L` 和 `A_R`。此时 `inv(A_L·T_L) · (A_R·T_R)` 通常不再等于原始的 `T_LR`，双手间距和相对姿态会被人为改写。

因此左右手只能共用一个 `T_align`。这个公共刚体变换可以改变整段动作在工作区中的落点，但不会篡改动作内部的双手几何关系。

### 3. 冗余和碰撞必须在整段轨迹上求解

每台 FR3 有 7 个关节。末端位姿相同，肘部构型仍可能完全不同。逐帧独立 IK 不约束 null-space 连续性，容易在相邻帧间跳到另一条 elbow branch。Retarget 必须以整段双臂轨迹为优化对象，同时处理关节限位、奇异位形、速度、加速度和双臂互碰。

“几何模型中没有碰撞”也不是充分条件。真实系统还叠加了 base registration、TCP 标定、连杆几何和控制跟踪误差，因此最小间距必须满足 `d_min > d_safe`，而 `d_safe` 应由两臂不确定度反推，不能凭经验随手指定。

### 4. Retarget 不能改写原演示的监督语义

UMI 图像记录的是手真实位于 `T_demo` 时的视觉状态。若把监督 action 直接替换成明显不同的 `T_retarget`，observation 和 action 就不再来自同一个物理状态分布。

因此 `demo_raw`、`retarget_reference` 与 `executed_robot` 三套轨迹始终分开保存。默认训练监督仍来自 `demo_raw`，retarget 只作为可执行性和质量元数据。若要得到 embodiment-native 数据，正确路径是让 FR3 真机复现，再重新采集 FR3 侧的 observation-action 对。

## 如何验收“复现了同一条轨迹”

录制精度与复现精度必须分开报告。前者比较 UMI TCP 与独立 tracker；后者比较 FR3 的命令、FK 和独立物理测量，并把 `e_internal = T_cmd⁻¹·T_FK` 与 `e_physical = T_cmd⁻¹·T_GT` 同时保留。两者之差正是名义模型没有解释掉的系统误差。

评价也不能只看一条 global APE。共享 first-frame alignment 会主动消除常量 world-frame 偏置，适合检查轨迹形状和短时运动；absolute replay 固定 `T_WB`，用于检查真实桌面、物体与 TCP 的空间一致性。项目优先报告接触窗口，以及 40 ms、100 ms、400 ms、1 s 四个尺度的 relative pose error，再用 absolute GT 认证 metric scale。

在引入 UMI、retarget 和接触之前，还要先让 FR3 执行已知的 10 / 30 / 50 / 100 mm 平移与几何轨迹，单独测出机器人自身的 physical tracking 能力。否则录制误差和机器人误差会混在一起，谁也解释不清。

最终的数据准入分为两级：

- `training-valid`：通过 tracking、QC、双手一致性和 dual-FR3 executable 检查，可规模化进入训练集。
- `replay-certified`：在前者基础上，通过独立 physical replay benchmark，按 episode 或任务族抽样认证。

少量物理 benchmark 的通过不能被外推成“全数据都已认证”，所以这两个名字必须一直分开。

## 距离 3 mm，还差三道门

第一道门是**把被测物变成真正的刚体**。生产夹爪到货后，需要实测 marker layout、完成 Marker→TCP 六自由度标定，并验证拆装、开合和载荷下的重复性。在这之前，rig 口径的数字不能替代 TCP 口径。

第二道门是**把相机网络变成可复现的尺子**。`cam_09` 的旋转修正需要在另外两批数据上复验后上线；新的标定轮次必须各自满足完整覆盖，再比较跨轮外参和 TCP 结果。只有这样，2 mm 相机预算才有机会被真实数据收紧。

第三道门是**引入与本系统无关的裁判**。独立动态 6DoF tracker 要同时覆盖录制和复现，报告 p50、p95、速度分层、双手相对误差与接触窗口。没有这一步，就没有资格把“内部看起来一致”写成“端到端 3 mm”。

这三道门通过之后，已认证的 TCP 轨迹还可以反推腕部相机位姿，为 4D 重建提供强 camera trajectory；也可以反过来检验 dense 3D / 4D perception 在遮挡或 markerless 条件下能否逼近这条真值。方向不能颠倒：**先用独立证据建立 GT，再让感知模型逼近它，而不是用更复杂的模型替代真值。**

毫米级 UMI 轨迹与双 FR3 复现，最终交付的不是一条漂亮曲线，而是一条不会混淆对象、坐标系、时间、版本和认证责任的证据链。相机负责看见，优化器负责解释，机器人负责执行；只有独立测量系统有权回答，它们是否真的在毫米尺度上说了同一件事。
